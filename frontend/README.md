# frontend

React 웹앱. 소비자(모바일 폭) / 가맹점 / KCP 관리자 화면.

- 배포: Vercel (루트 디렉터리를 `frontend/`로 지정)
- 시연용 목업 HTML이 기준 화면입니다. 목업의 화면·문구를 이식합니다.

React + Vite (JavaScript). Node.js 20.19 이상 필요.

## 실행 방법

```bash
cd frontend
npm install      # 처음 한 번 (패키지 설치)
npm run dev      # 개발 서버 → http://localhost:5173
```

- `npm run build`: 배포용 파일을 `dist/`에 만듦
- `npm run lint`: 코드 검사 (oxlint)
- 백엔드 주소는 `.env.example`을 복사해 `.env`로 만들고 `VITE_API_BASE_URL`을 채움

## 폴더 구조

화면은 **역할별 폴더**로 나눠 둡니다. 새 화면은 해당 역할 폴더에 추가해 주세요.

```
frontend/src/
├─ main.jsx · App.jsx     앱 시작점 · 주소별 화면 연결(라우팅)과 로그인·역할 검사
├─ pages/                 화면 (화면 하나 = 파일 하나)
│  ├─ auth/               로그인 (모든 역할 공통)
│  ├─ consumer/           소비자 (휴대폰 폭) — 소비자 와이어프레임 v0 기준
│  ├─ store/              가맹점 콘솔 (PC)
│  └─ admin/              KCP 관리자 콘솔 (PC)
├─ components/            여러 화면에서 같이 쓰는 부품 (쿠폰 카드, 하단 메뉴, 콘솔 틀 등)
├─ api/                   모의 API — 백엔드 연결 시 이 폴더만 교체
│  ├─ api.js              API 함수 (함수 옆 주석에 제안 API 주소)
│  └─ seed.js             시연 시작 데이터
├─ auth/                  로그인 상태 관리 (현재 모의 로그인)
├─ hooks/                 화면에서 데이터 불러오는 도구
├─ utils/                 숫자·날짜 표시, 상태 문구, 다크 모드 등 작은 도구
├─ styles/app.css         화면 부품 디자인 (맨 아래 다크 모드 색)
└─ index.css              공통 색·글꼴·버튼 (디자인 기본값)
```

## 확정 사항 (팀 결정)

- 소비자·가맹점·KCP 관리자 **모두 구글 로그인**
- 쿠폰은 **정액권만** (정률 % 없음)

## 로그인 (현재: 모의 구글 로그인)

구글 연동·백엔드 로그인 API 전까지 `src/auth/mockAuth.js`의 가짜 로그인을 씁니다.
**Google로 계속하기**를 누르면 시연용 계정 목록이 나오고, 고른 계정의 역할에 따라 이동합니다.

| 시연용 구글 계정 | 역할 → 화면 |
|---|---|
| 지민 | 소비자 → `/home` |
| 과수원집 | 가맹점 → `/store` |
| 봄꽃상회 · 바다찬 | 가맹점 → `/store` |
| KCP 운영팀 | KCP 관리자 → `/admin` |

- 소비자 화면은 소비자 와이어프레임 v0(Figma) 기준입니다. 홈·기획전·상품은 **로그인 없이** 볼 수 있고, 결제·쿠폰함·MY에서 로그인합니다. 로그인 후 원래 화면으로 돌아옵니다(구매가 자동으로 진행되지는 않음).
- 로그인 안 한 상태로 `/store`, `/admin`에 들어가도 로그인 화면으로 보내고, 로그인 후 원래 화면으로 돌아옵니다.
- 다른 역할의 화면 주소로 들어가면 자기 역할의 첫 화면으로 보냅니다.

## 가짜 백엔드 (모의 API)

백엔드 API가 나오기 전까지 `src/api/api.js`가 서버 역할을 합니다.

- 화면은 `api.js`의 함수만 부릅니다. 진짜 백엔드가 나오면 함수 안쪽을 `fetch` 호출로 바꾸면 됩니다. (함수 옆 주석에 제안한 API 주소)
- 데이터는 브라우저 localStorage(`muruk.db`)에 저장됩니다. 역할을 바꿔 로그인해도 같은 데이터를 써서 장면이 이어집니다.
- 처음 상태는 `src/api/seed.js`이고 두 가지입니다. MY 화면 맨 아래 또는 콘솔 왼쪽 아래 버튼으로 바꿀 수 있습니다.
  - **기획전 진행 중 (기본)**: 앱을 열자마자 상품을 사면 쿠폰을 받을 수 있음 — 기획전 기간 11/1~11/30
  - **8장면 시연 시작 상태**: 기획전이 "조건 서명 중"이라 아직 쿠폰이 발급되지 않음 → 아래 1~3장면(한도 등록·서명·승인)을 해야 쿠폰이 나옴
- 블록 번호·체인 기록은 모의 값입니다.
- 예시 데이터를 바꾸면 `seed.js`의 `SEED_VERSION`을 올리세요. 브라우저에 저장된 예전 데이터가 자동으로 새 데이터로 바뀝니다.

## 다크 모드

MY → 설정 → 화면에 스위치 2개 (기본: 둘 다 끔 = 항상 밝게)

- **다크 모드**: 직접 켜고 끔
- **시스템 설정에 맞추기**: 켜면 휴대폰·PC 설정을 따라감 (이때 다크 모드 스위치는 시스템 상태만 보여주고 잠김)

소비자 화면에만 적용됩니다. 가맹점·KCP 콘솔은 그대로입니다. 색 값은 `styles/app.css` 맨 아래.

## 시연 8장면 순서

먼저 **"8장면 시연 시작 상태로"**를 눌러 처음 상태를 맞춘 뒤 진행합니다.

| # | 구글 계정 | 화면 | 할 일 |
|---|---|---|---|
| 1 | KCP 운영팀 | 입금·한도 | 과수원집 입금 → **한도 등록** |
| 2 | 과수원집 | 쿠폰 발행 | "첫 구매 감사" 쿠폰 **발행** |
| 3 | 과수원집 → KCP 운영팀 | 연합 기획전 → 기획전 승인 | 마지막 가게로 **서명** → 규칙 잠금 → KCP **승인** |
| 4 | 지민 | 홈 → 과수원집 상품 → 결제 | 다른 가게 쿠폰 2장 + 첫 구매 보너스 1장 **발급** |
| 5 | 지민 | 쿠폰함 | 받은 쿠폰 확인 (사용 가능 / 사용 완료 / 만료) |
| 6 | 지민 | 봄꽃상회 쿠폰 → 사용하기 → 결제 | 다른 가게에서 **사용** (25,000원 → 22,000원) |
| 7 | 지민 | 사용 결과 → "같은 쿠폰 다시 써보기 (시연용)" | **재사용 거절** → 발급·사용 기록 보기 |
| 8 | 봄꽃상회 → KCP 운영팀 | 정산 → 체인 기록 | 할인 부담·돌려받을 충전금, 전체 기록 **조회** |

역할을 바꿀 때는 로그아웃(소비자: MY → 로그아웃 / 콘솔: 왼쪽 아래) 후 다시 Google로 계속하기.

- 한도 등록 전에는 쿠폰 발행·기획전 서명이 막힙니다. 기획전 승인 전에 구매하면 기획전 쿠폰은 발급되지 않습니다.
- 선물·교환(MVP 확장)은 아직 없습니다.

## 실패 화면 보여주기 (발표 질의응답용)

소비자 **MY → 시연 도구**에서 고르면 와이어프레임 상태 화면을 실제로 띄울 수 있습니다.

| 고르는 것 | 보이는 화면 |
|---|---|
| 다음 구매 때 쿠폰 발급 실패 | ④-c 결제는 됐지만 쿠폰을 발급하지 못했어요 (한 번만) |
| 다음 쿠폰 사용 때 결제 실패 | ⑨-d 쿠폰을 사용하지 못했어요 · 쿠폰은 그대로 남음 (한 번만) |
| 연결 오류 | 공통 "연결이 불안정해요" — 다시 불러오기를 누를 때까지 |
