# frontend

React 웹앱. 소비자(모바일 폭) / 가맹점 / KCP 관리자 화면.

- 배포: Vercel (루트 디렉터리를 `frontend/`로 지정)
- 기준 화면: 기획·디자인 팀의 **목업 v3**(소비자 화면 · 가맹점 센터 PC · KCP 관리자)와 **소비자 UI 가이드 v2**(톤앤매너·컴포넌트)입니다. (2026-11-03, 와이어프레임 v0에서 교체)

React + Vite (JavaScript). Node.js 20.19 이상 필요.

## 실행 방법

```bash
cd frontend
npm install      # 처음 한 번 (패키지 설치)
npm run dev      # 개발 서버 → http://localhost:5173
```

- `npm run build`: 배포용 파일을 `dist/`에 만듦
- `npm run lint`: 코드 검사 (oxlint)
- 백엔드 주소는 `.env.example`을 복사해 `.env`로 만들고 `VITE_API_BASE_URL`을 채움

## 브랜치 구성 (프론트)

역할별로 브랜치를 나눕니다. 공통 코드는 `feature/frontend`에만 두고, 역할 브랜치는 그 위에 **자기 화면만** 더합니다.

```
feature/frontend               공통 — 로그인, 공통 부품, 모의 API, 디자인, 앱 틀
 ├─ feature/frontend-consumer  소비자 화면   (pages/consumer/, routes/consumerRoutes.jsx)
 ├─ feature/frontend-store     가맹점 센터   (pages/store/,    routes/storeRoutes.jsx)
 └─ feature/frontend-admin     KCP 관리자    (pages/admin/,    routes/adminRoutes.jsx)
```

- 역할 브랜치는 서로 **다른 파일만** 고치므로, develop에 차례로 합쳐도 충돌하지 않습니다. (공통 → 소비자 → 가맹점 → KCP 순서 권장)
- 공통 브랜치만 실행하면 로그인 화면만 있고, 역할 화면은 "화면을 찾을 수 없어요"로 나옵니다.
- 여러 역할이 같이 쓰는 코드(부품·API·디자인)를 고칠 때는 `feature/frontend`에서 고칩니다.

## 폴더 구조

화면은 **역할별 폴더**로 나눠 둡니다. 새 화면은 해당 역할 폴더에 추가해 주세요.

```
frontend/src/
├─ main.jsx · App.jsx     앱 시작점 · 역할별 주소 목록을 모아 붙이는 곳
├─ routes/                역할별 주소(URL) 목록 — 역할 브랜치마다 자기 파일만 고침
│  ├─ consumerRoutes.jsx  소비자
│  ├─ storeRoutes.jsx     가맹점 센터
│  └─ adminRoutes.jsx     KCP 관리자
├─ pages/                 화면 (화면 하나 = 파일 하나)
│  ├─ auth/               로그인 (모든 역할 공통)
│  ├─ common/             없는 주소 안내 등 공통 화면
│  ├─ consumer/           소비자 (휴대폰 폭) — 목업 v3 C-01~C-12 + 상태 화면
│  ├─ store/              가맹점 센터 (PC) — 목업 M1~M4
│  └─ admin/              KCP 관리자 (PC) — 목업 K1~K3
├─ components/            여러 화면에서 같이 쓰는 부품 (쿠폰 카드, 하단 메뉴, 콘솔 틀 등)
├─ api/                   모의 API — 백엔드 연결 시 이 폴더만 교체
│  ├─ api.js              API 함수 (함수 옆 주석에 제안 API 주소)
│  ├─ core.js             규칙: 발급·사용 검증 (api.js와 seed.js가 같이 씀)
│  └─ seed.js             시연 시작 데이터
├─ auth/                  로그인 상태 관리 (현재 모의 로그인) · 역할 검사 문지기(RequireRole)
├─ hooks/                 화면에서 데이터 불러오는 도구
├─ utils/                 숫자·날짜 표시, 상태 문구, 다크 모드 등 작은 도구
├─ styles/app.css         화면 부품 디자인 (맨 아래 다크 모드 색)
├─ index.css              공통 색·글꼴·버튼·칩·안내 상자 (UI 가이드 v2 색 토큰)
└─ public/logo.png        무럭무럭 로고 (목업에서 꺼냄)
```

## 확정 사항 (팀 결정)

- 소비자·가맹점·KCP 관리자 **모두 구글 로그인**
- 쿠폰은 **정액권만** (정률 % 없음)
- **예치금·충전금 없음** (법률 문제로 폐지, 2026-11-03): 가게는 돈을 미리 맡기지 않고 **할인 한도(상한)**만 정함. 쿠폰이 실제로 쓰였을 때만 그 가게에 할인 부담. 최대 발급 수 = 할인 한도 ÷ 할인 금액, 다 발급되면 그 가게 쿠폰만 멈추고 기획전은 계속
- 가게는 쿠폰 조건을 **기획전에 등록**, KCP는 **가맹점 심사 · 기획전 만들기 · 시작 승인 · 일시 중지 · 종료 · 기록 조회**

아직 정해지지 않아 화면에 [가정]으로 넣은 것 (회의에서 확인 필요)

- 시작된 기획전의 쿠폰 조건은 가게가 바꿀 수 없음 (목업 메모: "KCP가 바꿀 수 있는 범위는 회의에서 정해요")
- 일시 중지·종료 중에는 새 쿠폰 발급만 멈추고, 이미 받은 쿠폰은 유효기간까지 쓸 수 있음

## 로그인·회원가입

```
Google로 계속하기 → 데이터베이스에 있는 계정인가?
  ├─ 있음: 소비자 /home · 가맹점 /store · KCP /admin
  └─ 없음: 회원가입 /signup → "무럭무럭 이용자이신가요? / 가맹점이신가요?"
       ├─ 이용자: 이름·동의 → 가입 완료 → 시작 (원래 보던 화면으로)
       └─ 가맹점: 가게 정보 → 대표 상품·동의 → 참여 신청 → KCP 심사 대기
            └─ KCP 가맹점 심사에서 승인 → 가맹점 센터 / 반려 → 안내 화면
```

**진짜 백엔드로 로그인하기:** `.env.example`을 복사해 `.env`를 만들고 `VITE_API_BASE_URL`, `VITE_GOOGLE_CLIENT_ID`를 넣은 뒤 서버를 다시 켭니다. 구글 콘솔의 "승인된 JavaScript 원본"에 `http://localhost:5173`이 있어야 합니다.

ID 토큰으로 관리자(`POST /api/admin/auth/google`) → 가맹점(`POST /api/merchants/auth/google`) → 소비자(`POST /api/auth/google`) 순서로 물어봅니다. 소비자 호출에서 `isNewUser: true`면 이용자·가맹점 선택 화면으로 갑니다. 가맹점을 고르면 `POST /api/merchants`로 신청합니다. 호출 도구는 `api/http.js`, 흐름은 `auth/mockAuth.js`입니다.

**연결 현황:** 로그인·가입만 진짜 백엔드와 연결합니다. 쿠폰·주문·기획전 등 나머지 화면은 아직 모의 API입니다. 전체 대조는 팀 노션 API 명세서 기준입니다.

두 값이 없으면 **Google로 계속하기**에서 구글 이메일을 직접 입력하는 임시 모드로 동작하고, 계정 확인은 모의 데이터베이스(`api/seed.js`의 `accounts`)에서 합니다.

| 이메일 | 결과 |
|---|---|
| jimin@example.com | 소비자 → `/home` |
| orchard@example.com · flower@example.com · sea@example.com | 가맹점 센터 → `/store` |
| ops@example.com | KCP 관리자 → `/admin` |
| 그 밖의 이메일 | 회원가입 → `/signup` |

- KCP 관리자는 회원가입이 없고 미리 만들어 둔 계정만 있습니다.
- 약관 본문은 아직 없어 동의 항목 이름만 있습니다. 동의는 서버에 저장하지 않습니다. 사업자등록번호는 숫자 10자리인지만 봅니다.
- 시연 데이터를 처음으로 되돌리면 가입한 계정도 사라집니다.
- 홈·기획전·상품은 **로그인 없이** 볼 수 있고(처음 실행 때 나오는 로그인 화면은 닫기로 건너뜀), 결제·쿠폰함·MY에서 로그인합니다. 로그인 후 원래 화면으로 돌아옵니다(구매가 자동으로 진행되지는 않음).
- 로그인 안 한 상태로 `/store`, `/admin`에 들어가도 로그인 화면으로 보내고, 로그인 후 원래 화면으로 돌아옵니다.
- 다른 역할의 화면 주소로 들어가면 자기 역할의 첫 화면으로 보냅니다.

## 가짜 백엔드 (모의 API)

백엔드 API가 나오기 전까지 `src/api/api.js`가 서버 역할을 합니다.

- 화면은 `api.js`의 함수만 부릅니다. 진짜 백엔드가 나오면 함수 안쪽을 `fetch` 호출로 바꾸면 됩니다. (함수 옆 주석에 제안한 API 주소)
- 데이터는 브라우저 localStorage(`muruk.db`)에 저장됩니다. 역할을 바꿔 로그인해도 같은 데이터를 써서 장면이 이어집니다.
- 처음 상태는 `src/api/seed.js`이고 두 가지입니다. MY 화면 맨 아래 또는 콘솔 왼쪽 아래 **시연 도구**로 바꿀 수 있습니다.
  - **기획전 진행 중 (기본)**: 앱을 열자마자 상품을 사면 쿠폰을 받을 수 있음 — 기획전 기간 11/1~11/30. 다른 손님 4명의 지난 이틀 구매·사용 기록이 들어 있어 가맹점·KCP 화면에도 숫자가 보임
  - **시연 시작 상태**: 기획전이 "준비 중"(과수원집 쿠폰 조건 미등록)이라 아직 쿠폰이 발급되지 않음 → 아래 1~3장면을 해야 쿠폰이 나옴
- 기록 번호(`0x9f…3a`)·체인 기록은 모의 값입니다.
- 예시 데이터를 바꾸면 `seed.js`의 `SEED_VERSION`을 올리세요. 브라우저에 저장된 예전 데이터가 자동으로 새 데이터로 바뀝니다.

## 검색 (`/search`)

홈 검색창을 누르면 검색 화면으로 갑니다. 쇼핑 앱(네이버쇼핑·PAYCO 등)이 흔히 쓰는 화면 흐름입니다. 로그인 없이 쓸 수 있습니다.

**검색 전용 API는 없습니다.** `GET /api/campaigns`로 받은 기획전 목록을 프론트에서 거릅니다 (`utils/search.js`).

- **검색 대상**: 기획전 이름 · 참여 가게 이름 · 상품명. 끝난 기획전은 뺍니다
- **입력 전**: 최근 검색어(이 기기에만 저장, 하나씩 지우기·전체 삭제·자동저장 끄기), 기획전·참여 가게 이름
- **입력 중**: 자동완성, 일치한 글자 강조
- **결과**: 결과 수, 정렬(추천순·낮은 가격순·높은 가격순), "쿠폰 받는 상품만" 필터, 상품마다 "구매하면 다른 가게 쿠폰 N장 · 최대 할인"
- **결과 없음**: 다시 찾는 방법 안내 + 기획전·가게 이름 추천
- 띄어쓰기·가운뎃점 무시("꽃 다발" = "꽃다발"), 여러 단어는 모두 들어간 상품만("제주 감귤"), 초성 검색("ㄱㄱ" → 감귤)
- 검색어는 주소(`?q=`)에 남아 뒤로 가기로 이전 결과에 돌아갑니다
- 모의 API `getCampaigns`의 응답 모양(참여 가게마다 상품 포함)은 가정입니다. 백엔드 응답과 다르면 `utils/search.js`의 `toSearchRows`만 고치면 됩니다

## 시작 화면·로딩 캐릭터

- **시작 화면**(`components/SplashScreen.jsx`): 디자인 시안 그대로. 소비자 앱을 새 탭으로 열 때 한 번 약 3.6초 나오고, 누르면 넘어갑니다(최소 1.5초). 다시 보려면 탭을 새로 여세요. 그림은 `public/splash/`.
- **처음 실행 때 첫 화면**(`utils/startup.js`): `/`, `/home`으로 들어왔을 때 로그인 안 했으면 시작 화면 뒤에 로그인 화면이 나오고, 닫기(X)를 누르면 비회원으로 홈에 갑니다. 로그인했으면 역할별 첫 화면으로 갑니다. 상품 링크처럼 다른 주소로 바로 들어오면 그 화면을 그대로 보여줍니다.
- **새싹이**(`components/SproutLoading.jsx`): 시안에서 캐릭터 부분만 사용. 소비자·가맹점 화면의 결제, 쿠폰 사용, 구매 확정·취소, 쿠폰 조건 등록에서는 씨앗→꽃으로 자라고, 화면을 불러올 때는 통통 뜁니다. 화면 불러오기·로그인·가입처럼 금방 끝날 수 있는 곳은 300ms가 넘을 때만 보입니다.

## 시연 8장면 순서

먼저 시연 도구의 **"시연 시작 상태로"**를 눌러 처음 상태를 맞춘 뒤 진행합니다.

| # | 구글 계정 | 화면 | 할 일 |
|---|---|---|---|
| 1 | KCP 운영팀 | 가맹점 심사 | 들꽃공방 참여 신청 **승인** (승인된 가게만 기획전 참여) |
| 2 | 과수원집 | 쿠폰 조건 설정 | 할인·최소 주문·유효기간·할인 한도 입력 → **기획전에 등록하기** (3/3) |
| 3 | KCP 운영팀 | 연합 기획전 관리 | 조건 3/3 확인 → **시작 승인하기** (진행 중) |
| 4 | 지민 | 홈 → 과수원집 상품 → 결제 → **구매 확정하기** | 다른 가게 쿠폰 2장 **잠김으로 발급** → 구매 확정으로 사용 가능 |
| 5 | 지민 | 쿠폰함 | 받은 쿠폰 확인 (탭 3개: 사용 가능 / 사용 완료 / 만료, 잠김·처리 중은 배지로 표시) |
| 6 | 지민 | 봄꽃상회 쿠폰 → 사용하기 → 결제 → **구매 확정하기** | 결제 적용(25,000원 → 22,000원) 후 **처리 중** → 구매 확정으로 **사용 완료** |
| 7 | 지민 | 사용 결과 → "같은 쿠폰 다시 써보기 (시연용)" | **재사용 거절** → 발급·사용 기록 보기 |
| 8 | 봄꽃상회 → KCP 운영팀 | 대시보드·할인 부담 내역 → 기록 조회 | 쓰인 만큼만 생긴 할인 부담, 전체 기록 **조회** |

역할을 바꿀 때는 로그아웃(소비자: MY → 로그아웃 / 콘솔: 왼쪽 아래 또는 오른쪽 위 계정) 후 다시 Google로 계속하기.

- 쿠폰 상태는 쿠폰 정책표(2026-11-04) 기준 6개입니다. 잠김 쿠폰에서 주문을 취소하면 소멸(쿠폰함에 표시 안 함), 처리 중 쿠폰에서 주문을 취소·환불하면 다시 사용 가능으로 돌아옵니다. 구매 확정 후에는 환불 버튼이 없습니다. 지금은 모두 모의 데이터로만 동작합니다.
- 쿠폰 조건이 모두 등록되기 전에는 시작 승인이 막힙니다. 기획전이 진행 중이 아닐 때(준비 중·일시 중지·종료) 구매하면 기획전 쿠폰은 발급되지 않습니다.

## 실패·확인 중 화면 보여주기 (발표 질의응답용)

소비자 **MY → 시연 도구**에서 고르면 목업 상태 화면을 실제로 띄울 수 있습니다.

| 고르는 것 | 보이는 화면 |
|---|---|
| 다음 구매 때 쿠폰 1장 발급 실패 | 쿠폰 1장을 발급하지 못했어요 · 받은 쿠폰 / 받지 못한 쿠폰 (한 번만) |
| 다음 구매 때 "발급 확인 중"에서 멈춤 | 쿠폰 발급을 확인하고 있어요 · 3단계 진행 (한 번만, 쿠폰은 실제로 발급됨) |
| 다음 쿠폰 사용 때 결제 실패 | 쿠폰을 사용하지 못했어요 · 쿠폰은 그대로 남음 (한 번만) |
| 다음 쿠폰 사용 때 "사용 확인 중"에서 멈춤 | 쿠폰 사용을 확인하고 있어요 · 같은 쿠폰으로 다시 결제하지 마세요 (한 번만) |
| 연결 오류 | 공통 "연결이 불안정해요" — 다시 불러오기를 누를 때까지 |

- 쿠폰이 한도까지 다 발급된 가게가 있으면, 시연 도구 없이도 같은 "발급하지 못했어요(사유: 소진)" 화면이 나옵니다.
